내 데이터 진단하기

전부 브라우저 안에서 로컬로 실행된다. 로그 파일은 이 기기를 떠나지 않는다. 업로드도, 가입도 없다.

데스크톱 브라우저 필요. 로그는 Claude Code가 실행되는 기기(~/.claude/projects)에 있다. 모바일 브라우저에서는 접근할 수 없다.
저장은 선택이고, 누르지 않으면 켜지지 않는다. 진단 후 "이 브라우저에 저장"을 누르면 결과가 이 브라우저의 저장 공간에 남아, 다음 진단이 이번에 끝난 지점부터 이어질 수 있다. 서버로는 가지 않고 버튼 하나로 지운다. 공용·공유 컴퓨터에서는 저장하지 말 것. 이 브라우저 프로필을 다음에 쓰는 사람에게 결과가 그대로 남는다. 진단만 돌리면 아무것도 남지 않는다.

돌리기 전에: 이 페이지가 무엇을 하고, 무엇을 하지 않나

  • 로그 파일은 이 기기를 떠나지 않는다. 읽기·판정·그래프가 전부 이 탭 안에서 끝난다. 2번 카드에서 "이 브라우저에 저장"을 누르지 않으면 탭을 닫는 순간 전부 사라진다. 저장을 누르면 이 컴퓨터의 브라우저 저장 공간에만 기록되고, 서버로는 전송되지 않으며, 버튼 하나로 언제든 지울 수 있다. 진단만 돌리면 네트워크 요청이 0건이다. F12 → Network 탭을 열어둔 채 실행해 직접 확인할 수 있다.
  • 전송은 3번 카드의 버튼을 눌러야만 일어난다. 그때 나가는 것도 화면에 미리 보여준 집계 숫자(일별 건수·합계), 직접 입력한 닉네임, 그리고 관측소가 이 기계를 같은 제출자로 알아보게 하는 단방향 해시 최대 16개뿐이다. 대화 내용·파일 경로·세션 ID·시각은 제출 스키마에 아예 없다.
  • 그 해시가 왜 있고, 무엇인가. 관측소는 모든 행을 더한다. 그래서 한 사람이 두 번 제출하면 두 번 세어졌다. 여기엔 로그인이 없으므로, 이 페이지는 로그 안에 이미 들어 있는 request ID로 이 기계의 고정 익명 식별자를 만든다. 정해진 규칙으로 일부를 고르고 각각을 SHA-256으로 해시해서, 다이제스트만 보낸다. request ID 자체는 나가지 않고 해시에서 되돌릴 수도 없으며, 관측소는 받은 다이제스트를 한 번 더 해시해서 저장한다. 그래서 공개 데이터를 읽는 사람이 손에 쥐는 값으로는 아무것도 되돌려 보낼 수 없다. 보낼 목록 전체는 3번 카드의 JSON 미리보기에 그대로 나온다.
  • 빌드 스텝이 없다. 브라우저가 실행하는 코드가 repo에 올라간 파일 그대로다. view-source와 GitHub를 한 줄씩 대조할 수 있다.
  • 로그인도 계정도 없다. Anthropic 계정이나 API와는 어떤 통신도 하지 않고, 로그 파일을 읽기만 한다.
이 사이트가 어떻게 구성돼 있나 (파일 지도)
  • assets/parse.js: 유실 판정 엔진. 이 페이지의 모든 숫자가 여기서 나온다. CLI scripts/check_cache_loss.py와 같은 규칙이며, 두 결과가 같은지 자동 테스트로 대조한다.
  • assets/charts.js: 그래프·히트맵 그리기 전용. 판정 계산은 하지 않는다.
  • assets/store.js: 선택적 로컬 저장. 이 컴퓨터의 브라우저 저장 공간만 건드리고 네트워크는 쓰지 않으며, 저장 버튼을 누르고 확인했을 때만 동작한다. 예외는 3번 카드에서 설명하는 연결 토큰 하나뿐이고, 지문을 만들 수 없었던 제출에서만 저장된다.
  • assets/identity.js: 기계 지문. 불러온 로그에서 request ID를 읽어 최대 16개를 골라 이 자리에서 해시한다. 스캔이 짧으면 고른 자리가 겹쳐 그보다 적다. 네트워크를 쓰지 않고 아무것도 저장하지 않는다.
  • functions/api/submit.js: 서버에서 도는 유일한 코드. 제출 버튼을 눌렀을 때만 호출되고, 스키마 검증 후 공개 repo에 커밋한다. 제출 1건이 커밋 1건인 건 그대로이고, 아래 네 파일을 그 한 커밋에 함께 쓴다.
  • data/submissions.json: 색인. 제출한 기계 1대가 1행이고 합계만 담는다.
  • data/daily.json: 전체 일자별 시계열. 달력 하루가 1행이고 모든 기계를 합산한 값이다.
  • data/identity.json: 제출한 기계의 해시된 지문과 연결 토큰 해시를 제출 id별로 담는다. 여기 다른 파일과 똑같이 공개돼 있고 이 링크로 바로 열린다. 다만 관측소 페이지가 내려받지 않을 뿐이고, 색인에서 빼낸 이유가 바로 그것이다. 저장되는 값은 브라우저가 보낸 값을 한 번 더 해시한 것이라, 여기서 값을 복사해도 누구도 행을 바꿀 수 없다.
  • data/subs/<id>.json: 내 제출의 일자별 원본. 제출 목록의 내 행에서 링크된다. 색인 행의 합계는 이 파일의 합과 정확히 같다.
  • wrangler.toml: 서버 설정도 repo에 공개. 숨겨진 백엔드가 없다는 뜻이다.

1 · 세션 로그 불러오기

설치 없이 3단계.

  1. Claude Code 로그 폴더를 찾는다: ~/.claude/projects (Windows: C:\Users\<사용자명>\.claude\projects).
  2. 그 폴더를 아래에 끌어다 놓거나, 버튼으로 선택한다. 여러 개의 .jsonl 파일도 된다.
  3. 결과를 읽는다. 파싱은 이 탭 안에서만 일어난다. 2번 카드에서 "이 브라우저에 저장"을 고르지 않으면 탭을 닫을 때 전부 사라진다.

폴더(또는 .jsonl 파일)를 여기에 드래그 앤 드롭

또는

낱개 .jsonl 파일이 드롭되었다. 낱개 파일은 subagents 폴더 판별이 불가능해 전부 메인 세션(30분 TTL)으로 분류된다. 정확한 판정을 원하면 폴더째 드롭하거나 폴더 선택을 권장.
폴더 접근이 안 되면? CLI 스크립트의 JSON 출력 붙여넣기

로그가 있는 기기에서 python scripts/check_cache_loss.py --json(이 repo에 포함된 스크립트)을 실행하고, 출력 전체를 아래에 붙여넣는다. 붙여넣는 JSON에는 집계만 담긴다: 총계와 일별 카운트.

참고: --json 플래그는 이 repo 사본에 추가된 것이고, 판정 규칙은 v2.1 그대로다.

TTL-strict 판정 v2.1: 캐시 TTL 안쪽에서 일어난 유실만 집계하고, 정당한 만료는 제외한다.

유실 판정 기준 (TTL-strict, v2.1)
  • 후보: 서버가 직접 message.diagnostics.cache_miss_reason = previous_message_not_found를 찍은 레코드만. 추정은 없다.
  • in-TTL 유실: 같은 세션 파일에서 직전 요청과의 유휴 간격이 30분 미만(메인 세션) / 5분 미만(서브에이전트)일 때. 그보다 길면 정당한 TTL 만료로 보고 집계하지 않는다.
  • iron 유실: 유휴 간격 5분 미만. 공표된 어떤 TTL로도 캐시가 만료됐을 수 없다.
  • 중복 제거: requestId당 1건. 같은 요청의 후속 레코드는 빠진 사유를 보강하는 데만 쓴다.
  • 비용: 유실 1건의 재과금 비용 = 그 요청의 cache_creation_input_tokens.

이 결과를 이 브라우저에 남기기 (선택)

자동 저장은 없다. 버튼을 누르면 총계·일별 집계·시간대별 요청 수·이 기계의 지문 해시가 이 컴퓨터의 브라우저 저장 공간에 기록된다. 서버로는 가지 않고, "저장된 기록 지우기"를 누르면 즉시 지워진다. 저장해 두면 다음 진단이 마지막 제출 다음 날부터 시작되므로 이미 보낸 기간을 다시 보내지 않아도 된다. 이 카드에 적히는 기간은 모두 UTC 기준으로, 위 그래프가 아니라 제출 카드와 같은 기준이다. 공용·공유 컴퓨터에서는 저장하지 말 것.

이 브라우저에 저장된 기록이 없다.

3 · 관측소에 집계 공유하기 (선택)

전송되는 것은 아래 JSON 전문 그대로다. 기간·총계·일별 카운트, 그리고 이 기계를 한 행으로 유지하는 단방향 지문 해시뿐. 로그·파일 경로·세션 내용·건별 상세는 절대 전송되지 않는다. 공유 기간을 좁히면 총계도 그 기간으로 다시 계산된다. 이 카드의 날짜는 위 화면과 달리 UTC 기준이다. 여러 나라의 제출을 날짜별로 더하는 자리라, 각자의 현지 날짜로 자르면 전체 일별 합계가 어긋나기 때문이다. 아래 기간 선택도 실제로 전송될 UTC 날짜를 보여 준다.
