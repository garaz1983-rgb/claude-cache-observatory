How losses are judged (TTL-strict, v2.1)
  • Candidate — a record the server itself stamped with message.diagnostics.cache_miss_reason = previous_message_not_found. Nothing is inferred.
  • In-TTL loss — the idle gap to the previous request in the same session file is under 30 minutes (main session) or 5 minutes (subagent). Longer gaps are legitimate TTL expiries and are not counted.
  • Iron loss — idle gap under 5 minutes: no published TTL could have expired the cache.
  • Dedup — one event per requestId; a later record of the same request may only back-fill a missing reason.
  • Cost — the re-billed cost of a loss is that request's cache_creation_input_tokens.
